# Проверка StartupTidy 1.3.1

Дата: 25 октября 2026 года. Сборка: встроенный компилятор .NET Framework 4.x, без внешних библиотек. Приложение запускается без запроса повышения прав.

## Автоматические проверки — 17 PASS

1. По умолчанию список пуст, наблюдение ограничено по времени.
2. Путь внутри Windows защищён.
3. Собственный EXE защищён.
4. Известное защитное имя процесса запрещено.
5. Файл с расширением, отличным от .exe, запрещён.
6. Папка WindowsExtra не принимается за Windows.
7. JSON сохраняется и читается, интервал ограничивается допустимыми значениями.
8. При замене настроек сохраняется резервная копия.
9. Повреждённый JSON отклоняется.
10. У тестового процесса определяются полный путь, тот же владелец и сеанс.
11. Выключенное правило оставляет тестовый процесс работать.
12. Одинаковое имя файла в другой папке не совпадает с правилом.
13. Фоновый тестовый процесс без окна остаётся работать при обычном закрытии.
14. Отменённая проверка не завершает процесс.
15. Принудительное завершение тестового процесса с сопоставлением пути без учёта регистра.
16. Обычное закрытие окна тестового процесса.
17. Путь в команде автозапуска заключён в кавычки.

В тестах запускались и закрывались только специально собранные TidyTestDummy.exe. Реальные приложения пользователя в правила не добавлялись.

## Проверка интерфейса

Главное окно открыто на рабочем столе Windows. Визуально проверены список, кнопки, русские надписи, статус остановленного наблюдения и вкладка настроек с исходными значениями 10 секунд / 3 минуты / автозапуск выключен. Окно выбора из запущенных приложений открывается и заполняется; отмена возвращает в главное окно.

## Границы проверки

Реальная запись в автозагрузку не включалась; вход в систему и перезагрузка не выполнялись. Отказ доступа к процессу другого пользователя и процессу с повышенными правами не воспроизводился отдельным тестом; проверки владельца/сеанса и обработка ошибок присутствуют в исходнике. Проверка не доказывает, что выбранное стороннее приложение не перезапустится через свою службу или задачу.

## Исправление повторного запуска в 1.0.1 — 21 UI PASS

Перед исправлением ошибка воспроизведена на трёх сохранённых правилах с включёнными и выключенными галочками. Получен тот же стек `NullReferenceException` в обработчике `MainForm.BuildUi` / `ListView.OnItemChecked`, что и на пользовательском скриншоте.

После исправления пройдены три цикла открытия заполненного списка: отсутствие исключений, восстановление трёх строк и смешанных галочек, отсутствие перезаписи файла при открытии, скрытие/восстановление окна, принудительное пересоздание нативного окна списка и отсутствие перезаписи настроек после него — 18 проверок. Дополнительно проверены сохранение одной изменённой галочки, сохранность способа закрытия и фоновый запуск с непустым списком — ещё 3 проверки.

Итого: 17 исходных проверок + 21 новая проверка интерфейса = 38 PASS. Настройки и чтение автозапуска в UI-тесте изолированы от реальных данных пользователя. Повторный вход в Windows и реальное изменение автозагрузки по-прежнему не выполнялись.
